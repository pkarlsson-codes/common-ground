Property Registry

The trust's land and the homes on it: what the trust owns, what each home is, what it was assessed at, who may buy it, and where it stands in being sold.

Projects: src/CommonGround.PropertyRegistry, src/CommonGround.PropertyRegistry.Contracts. Last checked against the code: 2026-11-13. Read the Architecture Overview and the Shared Kernel page first.

1. What it is

The CLT idea behind it. A community land trust buys land and keeps it for good. Homes on that land are sold to households with modest incomes. The household owns the house; the trust keeps the land and leases it to the household under a ground lease. The lease caps the price when the house is resold, so it stays affordable for the next buyer. Before any of that can happen, the trust needs a record of its land and its homes. That record is this context.

What it owns:

  • Land parcels: the land the trust holds, with its legal parcel number, address, size, how and when the trust acquired it, and any covenant terms. A parcel can be decommissioned and recommissioned. It is never sold.
  • Homes: each home on a parcel, with its type, bedrooms, bathrooms, size, year built, accessibility, assessment history, and income limit (the most a buying household may earn, as a percent of area median income).
  • Development projects: new construction on a parcel, or rehabilitation of homes already on it.

2. Project layout

The code follows the layout every context uses, with three aggregate folders under Domain/: LandParcels, Homes and DevelopmentProjects. It publishes integration events, so it has a CommonGround.PropertyRegistry.Contracts project.

Project references: SharedKernel, HomeBuyers.Contracts and Homeownership.Contracts (events it consumes), its own Contracts (events it publishes), and TrustManagement. The TrustManagement reference is only for TrustSeedLookup in the seeders.

Older names. A home used to be called a unit, and some code still says so: UnitAssessment, Home.UnitType, GetHome.UnitId, HomeAssessmentView.UnitId, and the file RecordUnitAssessment.cs, which holds RecordHomeAssessment. They all mean a home.

The arrows are IDs, not object references. Each aggregate is its own Marten stream, and no aggregate loads another.

ID prefixes: parcel- for LandParcelId, home- for HomeId, project- for DevelopmentProjectId.

LandParcel

  • Register needs a legal parcel number and an address, and an area above 0 acres. AcquisitionMethod is Purchase, Donation or Transfer.
  • Decommission and Recommission return null when the parcel is already in that state, so repeating the call does nothing.
  • A decommissioned parcel is hidden from the parcel list unless the caller asks for it (IncludeDecommissioned).

Home

  • Register needs bedrooms of 0 or more, bathrooms above 0 (1.5 is allowed), square footage above 0, and a year built from 1800 to five years after the current year. It also takes the first assessment.
  • UnitDesignation (for example "Unit B") tells apart homes on the same parcel. HomeLabel.Format joins it to the parcel address: "14 Alder Lane, Unit B". The label is built when read or published, never stored on the home.
  • IncomeLimitPercentOfAmi is 1 to 200, or null for a home sold at market rate with no limit. Home.DefaultIncomeLimitPercentOfAmi is 80. The portfolio import and HomesSeeder use it, and the web form starts at 80 from its own constant. Home.Register doesn't apply a default: null means no limit.
  • UnitAssessment.Create refuses a negative value and an assessment date after today in the trust's time zone. That is why RegisterHomeHandler.LoadAsync asks ITrustClock for today. RecordAssessment checks only that the value isn't negative; it doesn't check the date.
  • Each assessment is kept, oldest first. Assessed values are plain decimal, not Money.

DevelopmentProject

  • InitiateNewConstruction needs a name and a description. InitiateRehabilitation also needs at least one home ID.
  • The only event is DevelopmentProjectInitiated, so ProjectStatus is always Initiated. See section 12.

6. Home availability

Staff need to see where each home stands: free to offer, choosing a buyer, under contract, leased, or back with the trust. Those facts belong to HomeBuyers and Homeownership. HomeAvailabilityView collects their events per home and works out two values: Occupancy (Vacant or Occupied) and SaleStage.

stateDiagram-v2
  [*] --> Offered : home registered
  Offered --> InSelection : HomeSelectionStarted
  InSelection --> Offered : HomeSelectionCancelled
  InSelection --> UnderContract : ApplicationSelected
  UnderContract --> Offered : PurchaseFellThrough
  UnderContract --> NotForSale : GroundLeaseCreated
  Offered --> NotForSale : GroundLeaseCreated (direct)
  NotForSale --> AwaitingTrustDecision : ResaleOpened
  AwaitingTrustDecision --> NotForSale : ResaleWithdrawn
  AwaitingTrustDecision --> Offered : ResaleBoughtBack, offered
  AwaitingTrustDecision --> HeldByTrust : ResaleBoughtBack, held
  HeldByTrust --> Offered : release-for-sale

NotForSale means a homeowner leases the home (Occupied). Every other stage is Vacant.

Rules the code follows:

  • No view means available. A home has no HomeAvailabilityView until the first event about it arrives. GetHome, GetHomes and the Today query treat a missing view as Vacant and Offered.
  • It never refuses an event. The other contexts already decided; this view only records. Events can arrive in any order, so the view stores what it has heard of each selection and each resale, and Refresh() works out the stage from all of it every time. For example, a PurchaseFellThrough that arrives before its ApplicationSelected is kept in FellThroughBeforeSelected until the selection shows up.
  • The latest selection counts. HomeBuyers runs one selection per home at a time, so Refresh() uses the one that started last.
  • A buyback starts over. When the trust buys a home back, the lease and the selections before the buyback date no longer count.
  • A purchase with no application changes nothing. A purchase started directly, not from a selection, never showed the home under contract.
  • Concurrent handlers retry. The view uses Marten optimistic concurrency, so two handlers updating one home at once don't overwrite each other: the loser gets a ConcurrencyException and Wolverine reruns its handler, up to three times (RetryWithCooldown in src/CommonGround.API/Program.cs).

Release for sale is the one change staff make here. After a buyback where the trust chose to hold the home (for repairs, say), POST /api/homes/{id}/release-for-sale calls HomeAvailabilityView.Release, which moves the home to Offered. It raises no event. A home that isn't held gets property_registry.home.release_for_sale.not_held.

The view also records why and when a home became available again (AvailableAgainCause: PurchaseFellThrough, TrustBoughtBack or TrustReleased). The Today page shows it.

The logic is in Application/ReadModels/HomeAvailabilityView.cs; the handlers all go through Application/EventHandlers/HomeAvailabilityUpdate.cs. Unit tests: HomeAvailabilityViewTests and HomeAvailabilityUpdateTests.

8. Errors

Every rule above throws a factory from PropertyRegistryBusinessRuleViolation.cs, which the API returns as 422 with the code. Codes follow property_registry.<aggregate>.<operation>.<rule>, for example property_registry.home.register.year_built_out_of_range. Each code needs a message in BusinessRuleErrorMessageMap (see docs/ai/api-contracts.md).

An unknown HomeType or project type is checked in the endpoint and returns 400, not 422. A missing ID returns 404 in two ways: GetHome, GetLandParcel and GetDevelopmentProject throw AggregateNotFoundException, and a [WriteAggregate] command on a missing stream throws RequiredDataMissingException (OnMissing.ThrowException in Program.cs).

9. Work items for Today

GetPropertyRegistryWorkItems returns one home-available work item for each home whose sale stage is Offered, in the Selections area, with the action start-selection. The text says why it's available:

  • "Available, no selection started", dated the day the home was registered (in the trust's time zone), for a home that was never sold.
  • "Available again after a purchase fell through", "after the trust bought it back" or "after the trust released it", dated when that happened.

The logic is in PropertyRegistryWorkItems.ForHome, tested in PropertyRegistryWorkItemsTests. src/CommonGround.API/Today/TodayEndpoints.cs merges it with the other contexts' lists.

10. Queries for the rest of the API

Two queries exist for callers outside this context's endpoints. Both are sent through the bus, so the caller doesn't touch this context's documents directly.

  • GetRegisteredProperties: every parcel's ID and parcel number, and every home's ID, parcel and unit designation, decommissioned or not. The portfolio import uses it to match spreadsheet rows to what already exists.
  • GetHomeRegistrations: every home's ID and RegisteredAt. The funder report (src/CommonGround.API/Reports/FunderReportEndpoints.cs) turns each RegisteredAt into a date in the trust's time zone and uses it to place homes in the report period.

11. Seeding

LandParcelsSeeder, HomesSeeder and DevelopmentProjectsSeeder read land-parcels.seed.json, homes.seed.json and development-projects.seed.json, embedded from Infrastructure/Seeding. Entries refer to each other by seed key (a home names its parcel's seed key). The *SeedLookup documents map a seed key to the real ID, so a later seeder can find it and a rerun skips entries that already have a lookup.

Each entry names the trust it belongs to by its trust seed key. The seeder throws if TrustsSeeder hasn't run. The seeders don't send commands: they call the aggregate methods (LandParcel.Register, Home.Register, Home.RecordAssessment, DevelopmentProject.Initiate…) and start the streams themselves, inside SeedClock.RunAsync so each event is dated on its seed date. So the seed data passes the same domain rules as the endpoints, including UnitAssessment.Create.

12. Gaps and unused code

Rules nothing enforces

  • RegisterHome doesn't check that the land parcel exists or is active. A home can be registered on a decommissioned parcel through the API. If the parcel doesn't exist, the published HomeRegistered carries a label with an empty address.
  • DecommissionParcel doesn't check for homes on the parcel or for open ground leases.
  • Development projects don't check that the parcel exists, or that a rehabilitation's homes are on that parcel.
  • InitiateDevelopmentProjectRequest.Description is nullable, but the domain refuses a missing description with a 422.
  • POST /api/development-projects returns 201 Created with the list URL as its location, not the new project's URL.

Code with no callers

I searched src/; only the unit tests call these.

  • ListParcelForPlacement and its handler: no endpoint or code sends it.
  • LandParcel.ListForPlacement and LandParcel.WithdrawForRedevelopment, and their events ParcelListedForPlacement and ParcelWithdrawnForRedevelopment. LandParcel has no Apply for either event, so raising them would change no state.
  • ParcelConstructionStarted, ConstructionSuspended and ConstructionCompleted: nothing creates them.
  • ProjectStatus.Active, Completed and Abandoned: no event sets them.
  • The pg_trgm extension added in PropertyRegistryMartenConfiguration: no trigram index uses it. The parcel search is a case-insensitive Contains.
  • AddPropertyRegistry(): registers nothing.

13. Changing this context

  • New aggregate, event or value object: follow docs/ai/creating-domain-types.md and generate it with the templates/. Every event needs a public Apply (or Create) on the aggregate, or its state is lost when the stream is loaded.
  • New fact other contexts need: add it to the integration event in PropertyRegistry.Contracts, and update the consumers in HomeBuyers and Homeownership in the same change. Follow docs/ai/api-contracts.md.
  • New event from HomeBuyers or Homeownership that changes a home's stage: add a handler that goes through HomeAvailabilityUpdate, add a Record… method to HomeAvailabilityView, and handle the event arriving in any order. Add cases to HomeAvailabilityViewTests.
  • New list filter: filter in the query, not in memory after paging, or page counts go wrong. GetHomes shows the pattern for filtering on HomeAvailabilityView, including homes that have no view yet.
  • Dates: "today" is the trust's today from ITrustClock. See docs/ai/dates-and-times.md.
  • UI changes: update the journey doc in docs/journeys/ and the e2e spec in e2e/tests/.
