Shared Kernel

The project every bounded context builds on: base classes for aggregates, entities, IDs, value objects and enumerations; the events and errors they raise; the app's clock; and the Marten, Wolverine and seeding plumbing the contexts share.

Project: src/CommonGround.SharedKernel. Last checked against the code: 2026-11-13. Read the Architecture Overview first.

1. What it is

In Domain-Driven Design a shared kernel is the small part of the model that several bounded contexts agree to share, and change only together. Here it is one class library, CommonGround.SharedKernel. All seven bounded contexts, their *.Contracts projects, the API, both gateways, CommonGround.API.Clients, CommonGround.API.Contracts and CommonGround.Testing reference it: 17 projects in all. It references no other project in the solution.

It holds three kinds of code:

  • Domain building blocks (Domain/): the base classes every domain type derives from, the event and exception base types, and value objects that more than one context uses, such as Money and PersonName.
  • Cross-cutting services: the clock (TimeProviderContext, ITrustClock) and the work-item shape that Today collects.
  • Infrastructure (Extensions/, Infrastructure/): Marten setup, aggregate-loading helpers, Wolverine middleware, paging types, the base HTTP client the gateways use, and seeding support.

Because 17 projects depend on it, a change here can break any of them, and a change to a type stored in events (Money, an ID, an Enumeration) changes how stored events read back. Keep it small; see Adding to the shared kernel.

3. Domain building blocks

Every domain type in a bounded context derives from one of these. Don't write a domain type as a plain record, class or C# enum. Generate the skeleton with the dotnet new templates in templates/ (ddd-aggregate, ddd-entity, ddd-vo, ddd-enum); docs/ai/creating-domain-types.md has the full rules.

TypeUse it forRules
IEntityId<TSelf>Every ID: HouseholdId, LandParcelId, TrustId, UserId.A readonly record struct wrapping a string such as household-01jq…: a prefix, a hyphen and a lower-case ULID (EntityIds.New). Create(string) rejects a value without the prefix. Keep the prefix a private const: a public static property stops Marten and Wolverine treating the type as a strong-typed ID. Mark it [JsonConverter(typeof(EntityIdJsonConverter<TSelf>))] so it serializes as a plain string. The non-generic IEntityId has only Value, for code that takes any ID.
Entity<TId>An object with identity that lives inside an aggregate.Equal when the IDs are equal. The owning aggregate creates and changes it, only in its Apply methods.
AggregateRoot<TId>The root of an event stream: Household, GroundLease, LandParcel.A decider; see below. Adds no members to Entity: the base class marks the role.
ValueObjectA value with no identity: Money, PersonName, a lease's terms.Private constructor, validation in a static Create, equality from GetEqualityComponents(). Not a record.
Enumeration<T>A closed set of named values: a lease status, a violation type.Instances are static readonly fields. Events hold the enumeration itself; Marten stores its DisplayName through EnumerationJsonConverter. So a display name is a stored key: renaming one breaks every stored event that holds the old name. The web maps display names to the text staff see.

Aggregates are deciders

A decision method checks the request against the aggregate's state and returns the event it decides on, null when there is nothing to do, or a list for several events. It never changes state. Marten builds the aggregate from its stream by calling a public static Create for the first event and a public Apply for each later one. Both must be public: Marten's source generator skips non-public ones without an error, and that event's state is then missing when the aggregate is next loaded.

From src/CommonGround.PropertyRegistry:

// Domain/LandParcels/LandParcel.cs: the decision
public ParcelDecommissioned? Decommission(UserId changedBy)
{
    if (IsDecommissioned)
        return null;

    return new ParcelDecommissioned(Id.Value, changedBy.Value);
}

// Domain/LandParcels/LandParcel.cs: the evolution
public void Apply(ParcelDecommissioned _)
{
    IsDecommissioned = true;
}

// Application/Commands/DecommissionParcel.cs: the handler
public static ParcelDecommissioned? Handle(
    DecommissionParcel command,
    [WriteAggregate] LandParcel parcel)
    => parcel.Decommission(command.ChangedBy);

Wolverine's [WriteAggregate] loads the stream named by the command's LandParcelId, calls the handler, and appends whatever event it returns. The handler holds no logic of its own. When a check would be needed by two entry points, it belongs in the aggregate.

4. Domain and integration events

TypeWhat it isWhere it lives
DomainEvent(string AggregateId)A fact an aggregate decided on, stored in its stream. Base record for every domain event.The context's Domain/<Aggregate>/Events/.
IntegrationEventA fact one context publishes for others: HomeSelectionStarted, PurchaseClosed. Has its own EventId (a GUID).The publishing context's *.Contracts/Events/. Only HomeBuyers, PropertyRegistry and Homeownership have one.

Both set OccurredAt from TimeProviderContext.Current.UtcNow when the event object is constructed, not from DateTimeOffset.UtcNow. This is what lets seeding and tests fix the time an event happened (section 8). EventClockMiddleware then runs each handler of the event at that time.

IntegrationEvent.SourceBoundedContext takes the second segment of the event's namespace (CommonGround.HomeBuyers.Contracts.Events gives HomeBuyers). Moving an event to another namespace changes it. The code has a TODO about this.

A domain event's payload uses domain types where they are stable to store: Money, enumerations, IncomeLimitLevelEntry. ParcelDecommissioned above holds its IDs as plain strings (AggregateId, ChangedBy).

The API turns these exceptions into ProblemDetails responses. The handlers are in src/CommonGround.API/Infrastructure/ExceptionHandling/.

6. Shared value objects

These are here because more than one context uses them.

TypeWhat it is
MoneyUS dollars in whole cents. Create refuses a fraction of a cent; use it for an amount someone entered or stored. RoundedFrom and Share round a worked-out amount (interest, two-thirds of a balance) to the cent once, half a cent away from zero. Adding, subtracting and multiplying by an int stay in whole cents. May be negative, for a credit. Stored and sent as a plain JSON number (MoneyJsonConverter). Events carry Money; read models and API contracts use decimal and convert at the endpoint.
PersonNameA name as one string, 200 characters at most.
EmailAddressValidated, 254 characters at most.
PhoneNumberParsed and formatted with libphonenumber-csharp. FromOptional returns null for blank input.
IanaTimeZoneA time zone ID such as America/Chicago. ToDate turns an instant into the calendar date in that zone; ToInstant goes the other way.
IncomeLimitLevelOne row of a HUD income limit table: a percent of area median income (AMI) and a limit for each household size from 1 to 8.
IncomeLimitTableA copy of an income limit schedule as it stood on one day. A home selection keeps the one in effect when it starts and the purchase carries it, so later corrections to the schedule don't change what the purchase is judged by. BandFor(income, householdSize) gives the IncomeBand.
IncomeBandWhich levels a household's income falls between: over one level's limit and at or under the next. Used by HomeBuyers, Homeownership and reports.

Not every amount is converted to Money yet. docs/ai/creating-domain-types.md lists the ones still in decimal.

7. Marten and Wolverine helpers

AddMartenServices

The API calls this once, in src/CommonGround.API/Infrastructure/DependencyInjection.cs; a second call throws. It sets:

  • System.Text.Json serialization with EnumerationJsonConverter.
  • String stream keys (StreamIdentity.AsString), in schema commonground_events.
  • Conjoined tenancy for events and every document: one database, each row tagged with its trust's ID.
  • Lightweight sessions, Wolverine integration, and publishing every event to Wolverine.
  • The async projection daemon in Solo mode, and database schema changes applied at startup.

The API passes its own options on top: projections, indexes and document types.

Loading and deciding

HelperUse it when
[WriteAggregate] (Wolverine)The default. A handler that changes one aggregate named by an ID on the command.
stream.Decide(a => a.Something(…))[WriteAggregate] can't load the aggregate: the handler writes several streams, or an integration event names the aggregate by a plain string. Fetch the stream with FetchForWriting, then call Decide. A second Decide on the same stream sees the state the first one produced. Throws AggregateNotFoundException if the stream doesn't exist.
session.LoadAggregateAsync<T>(id)A handler needs another aggregate's state to decide, without writing to it. Throws AggregateNotFoundException if not found.
AggregateEvolver.Evolve(aggregate, events)Apply events to an aggregate in memory, through the same generated code Marten runs on load. Used by stream.Decide and by tests in CommonGround.Testing.

EventClockMiddleware

Wolverine delivers an event to its handlers after the event happened: through the Marten subscription or a durable queue. Without this middleware a handler's "now" would be the delivery time. The middleware runs each handler with the clock set to, in order of preference:

  1. the message's own OccurredAt, if it is a domain or integration event;
  2. otherwise the cg-clock envelope header, which messages cascaded from a timed handler inherit, or a scheduled message's due time, whichever is later;
  3. otherwise the clock is left alone.

This is how a seeded event dated last March gets its reactions dated last March too. The API registers it in Program.cs with EventClockMiddleware.Register(opts).

8. The clock

App code never reads DateTimeOffset.UtcNow or DateTime.Now. It reads TimeProviderContext.Current.UtcNow, or asks ITrustClock for a date.

TypeWhat it does
ITimeProviderOne property, UtcNow. Implemented by SystemTimeProvider (the real clock) and ControllableTimeProvider (a clock you set and advance).
TimeProviderContextA static holder, so domain events can read the time without dependency injection. Use(provider) sets a clock for the current async call chain only (an AsyncLocal) until the returned scope is disposed; seeding and EventClockMiddleware use it, and other requests keep the real clock. SetCurrent changes the global clock for the whole process; only tests call it.
ITrustClockCalendar dates in a trust's time zone: TodayAsync(trustId) and ToTrustDateAsync(trustId, instant). Implemented by TrustClock in TrustManagement, which reads the trust's IanaTimeZone. A date taken from UTC would put an evening event on the next day.

Instants are UTC DateTimeOffset; calendar dates are DateOnly. The full rules, including the web side (CalendarDate, trustToday()), are in docs/ai/dates-and-times.md.

9. Work items for Today

Today is the staff work queue. It is not a bounded context: the API's Today module asks each context for its work items and lists them together. The shared kernel defines the shape they all return:

  • WorkItem: the area, a kind (such as application-awaiting-decision), the record type and ID to open, a label and detail line, an optional due date, the date it has waited since, and the action keys staff can take, in the order to offer them.
  • WorkArea: the five area keys in the order a CLT's work runs: applicants, selections, purchases, stewardship, records.
  • WorkItemList: the wrapper a context's work-item query returns. A bare list from a Wolverine handler would be taken as messages to cascade, so it is wrapped.

HomeBuyers, PropertyRegistry, Homeownership and Documents return work items. The web app skips a kind it doesn't know.

11. Seeding

The API doesn't seed at startup. npm run db:seed runs dotnet run --project src/CommonGround.API -- seed, which runs every IDevelopmentSeeder and skips what is already seeded. The demo sandbox uses the same seeders for each new demo trust.

TypeWhat it does
IDevelopmentSeederOne method, SeedAsync(SeedRun, IDocumentStore, CancellationToken). Runs after the app has started, so the Marten subscription and Wolverine are running. It is not Marten's IInitialData, which runs during host startup, before events propagate, and in every environment. Implemented in the API, PropertyRegistry and TrustManagement.
SeedRunOne run of the seeders. SeedRun.Development (key dev) is what db:seed uses. A run with a Trust seeds the seed file's single trust under a new ID and name, which is how a demo trust is made.
SeedDateA date in seed JSON: a fixed ISO date (2021-09-15) or one relative to the day seeding runs (today, today-30d, today+2w, today-6m, today-5y), so seeded data doesn't go stale.
SeedClockSeedClock.RunAsync(timeZone, seed) sets a scoped clock for the seed and lets it MoveTo(date), at 10:00 in the trust's time zone by default. Events then carry the seeded date in OccurredAt.
PropagationWaiterWaits until no events or Wolverine messages are left to deliver (WaitForIdleAsync), or until a record a handler creates appears (WaitForAsync). A seeder calls it before it builds on what another context's handler made, or before it moves the seed clock on. Timeouts use real elapsed time, not the seed clock.

12. Code with no callers

These types are in the shared kernel but nothing outside it calls them. I searched src/ without the test projects. They are candidates for deletion; don't build on them without checking that they work.

  • Specification<T> and QueryableSpecificationExtensions.
  • PaginationQuerySpec and PaginationQuerySpec<TFilter>; PaginationQuerySpecV2 replaced them.
  • IQueryablePaginationExtensions. Its Sort ignores the sort descriptors (it orders by a constant; a TODO says so), and its TakeAsync uses Entity Framework Core's CountAsync and ToListAsync. It is the only reason the project references Microsoft.EntityFrameworkCore.
  • QueryableSortExtensions, SortDescriptor, and the model binder that is registered but never binds anything.
  • CursorHelper and CursorPaginatedResponse<T>.
  • CorrelationIdHandler: the gateways don't forward the correlation ID to the API.
  • PostalAddress, Coordinates and GeographicArea.
  • The CSharpFunctionalExtensions package reference: no file uses it.

13. Adding to the shared kernel

  • Add a type only when a second context needs it. Until then it belongs in the one context that uses it. Moving it here later is cheap; taking it out once 17 projects depend on it is not.
  • The same rule in two contexts is a missing type. Money came from repeated cents rounding in several contexts. When you see the same check twice, give it a name and a home.
  • Types stored in events can't change shape freely. Renaming an Enumeration display name, an ID prefix, or a Money JSON format changes how stored events read back. Keep accepting the old form, or write a Marten upcaster.
  • No context-specific language. A type here should mean the same thing in every context. IncomeLimitTable qualifies because HomeBuyers and Homeownership use the same HUD table in the same way.
  • New violations need messages. Add the factory to SharedKernelBusinessRuleViolation.cs with a shared. code, and its message to BusinessRuleErrorMessageMap.
  • Test it in CommonGround.SharedKernel.Tests, following docs/ai/unit-testing.md.
