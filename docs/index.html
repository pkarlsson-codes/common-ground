CommonGround developer docs

CommonGround is software for community land trusts (CLTs). These pages explain how it is built, for a developer who joins or forks the project.

The system, step by step

A community land trust buys land and keeps it for good. It sells the homes on that land to households with modest incomes and leases them the land under a ground lease. The lease caps the resale price, so the home stays affordable for the next buyer. Each step of that work has its own bounded context in the code.

  1. 1. The trust gets land and builds or buys homes on it.

    Property RegistryLand parcels, homes, development projects, and where each home stands in being sold.

  2. 2. Households apply to buy, and the trust picks one for each home.

    Home BuyersHouseholds, applications, choosing a household for a home, income limits.Page not written yet

  3. 3. The household buys the house and leases the land. Later they resell at a capped price.

    HomeownershipPurchase workflow, mortgages, ground leases, lease fee notices, resales.Page not written yet

  4. 4. The trust helps owners keep their homes.

    StewardshipStewardship cases and foreclosure prevention.Page not written yet

Used at every step

  • Trust ManagementThe trust's settings, policy, members and invitations.Page not written yet
  • IdentityUsers, linked to their Keycloak account.Page not written yet
  • DocumentsUploaded files attached to any record.Page not written yet

Under all of them

  • Shared KernelBase classes, shared value objects, errors, the clock, and the Marten and Wolverine helpers every context uses.

The API also has four modules that aren't bounded contexts: Today (the staff work queue), Reports, PortfolioImport and Demo. They work through the contexts' commands and queries. See Architecture Overview, section 4.

About these pages

The pages are static HTML with no build step. Open docs/index.html from disk or serve the folder with any static file server. Diagrams use Mermaid 11.4.1 from jsDelivr, so they need a network connection.

  • docs/docs.css holds the styles for light and dark mode.
  • docs/nav.js builds the header, the sidebar and the Previous and Next links. Its SITE list is the one place that lists the pages.

To add a page: copy an existing context page, add it to SITE in nav.js (or remove planned: true from its entry), and change its card on this page from a div to a link. Check it at 390px wide: the page must not scroll sideways.
