CommonGround — Authentication Flow

How a user gets a session and how that session becomes an authenticated API call. Management Gateway (:4000); the Homeowner Gateway follows the same pattern. Source of truth: docs/auth-flow.md.

(userId, trustId, access/refresh/id) G-->>B: Set-Cookie cg_auth, cg_session (HttpOnly), cg_csrf
302 to returnUrl

User provisioning is just-in-time — the gateway calls the API's EnsureUser during login using a service token (no user_id yet), and the API's canonical user ID is what goes into the session, not the Keycloak subject.

Authenticated API call

scroll to zoom · drag to pan
sequenceDiagram autonumber participant B as Browser participant G as Gateway participant R as Session store (Postgres) participant A as API B->>G: GET /api/… (cookies: cg_auth, cg_session) Note over G: cookie auth establishes principal Note over G: InternalGatewayAuthHandler (on outbound API client) G->>G: user_id from claims principal G->>R: lookup session by cg_session R-->>G: userId (fallback), trustId G->>G: mint internal JWT (5 min, HS256)
claims: user_id, tenant_id, session_id G->>A: forward request, Bearer internal JWT Note over A: validate issuer/audience/signature,
identity = user_id claim A-->>G: response G-->>B: response

The trust ID always comes from the session lookup, not from claims — a request with a valid cg_auth cookie but no session row gets a JWT without tenant_id. Keycloak tokens never cross the gateway→API boundary; the internal JWT is the only credential the API ever sees.

Token refresh

scroll to zoom · drag to pan
sequenceDiagram autonumber participant B as Browser participant G as Gateway participant R as Session store (Postgres) participant K as Keycloak B->>G: POST /auth/refresh (cg_session) G->>R: lookup refresh token alt no session or no refresh token G-->>B: 401 end G->>K: refresh_token grant K-->>G: new access (+ refresh) token G->>R: remove old sessionId,
save tokens under NEW sessionId G-->>B: Set-Cookie new cg_session + cg_csrf, 200

Refresh rotates the session ID: the old session row is deleted and new cookies are issued, so a captured cg_session value goes stale after the next refresh. Logout (GET /auth/logout) deletes the session row and cookies, then signs out of both the cookie scheme and Keycloak using the stored id_token as the logout hint.
